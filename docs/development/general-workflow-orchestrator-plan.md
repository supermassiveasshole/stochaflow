# 通用工作流编排器计划

> 工作状态：暂停
>
> 当前结论：普通 Python 的显式顺序组合应先解决真实任务。只有至少两条已维护
> 工作流反复需要相同的恢复、重试、分支或状态传递规则时，才重新讨论通用编排器。
>
> 规范来源：[`ROADMAP.md`](../../ROADMAP.md)、[`SPEC.md`](../../SPEC.md)、
> [`ARCHITECTURE.md`](../../ARCHITECTURE.md)
>
> 最后核对：2026-08-09

## 完成后用户能做什么

如果重复使用证据成立，用户可以用一个受限制的工作流执行层运行多步操作，查看每步
状态，并在明确规则下恢复或重试。这个执行层只协调已经存在的训练、采样、恢复和
Evaluation 操作，不解释教师模型、图像字段或算法私有配置。

## 当前仓库已经支持什么

- train、sample 和 evaluate 是配置与结果彼此独立的操作。
- checkpoint、prediction artifact、sampling artifact 和正式 Evaluation result 都有受治理
  的身份或发布边界。
- [显式顺序工作流计划](default-workflow-pipeline-support-plan.md)保留训练后蒸馏和生图后
  超分辨率两条首批路径。

这些基础足以让调用方先用普通 Python 组合步骤，不证明通用执行层已经必要。

## 还没有支持什么

- 没有通用的步骤图、状态机、恢复、重试、分支或并行执行契约。
- 没有证明两条已维护工作流需要相同控制字段的重复使用证据。
- 没有决定应复用外部编排工具、增加窄顺序执行器，还是继续使用普通 Python。
- 本文中的候选描述不是公共 API，也不是当前配置格式。

## 什么时候可以开始或重新审查

只有下面条件全部满足时才重新审查：

- 训练后蒸馏和生图后超分辨率，或另外两条真实工作流，已经作为独立操作组合持续维护；
- 至少两条工作流重复同一种恢复、重试、状态传递或失败处理；
- 手工组合已经造成可复现的维护问题，而不只是多写了几行 Python；
- workflow 维护者被明确指定，并能给出首个受限制的用户结果、预算和退出方案；
- 每个拟议公共字段都有两个独立使用者，任务私有字段仍由任务扩展负责。

## 要完成哪些工作

### 收集重复控制逻辑的证据

- 动作：对至少两条已维护工作流逐步比较失败、恢复、重试和状态传递行为。
- 原因：没有重复证据时，通用模型只会猜测未来任务的需求。
- 影响范围：工作流示例、运行记录和短决策记录；不修改运行时。
- 交付物：重复项、不同项、维护成本和不采用通用编排器的可行方案。
- 验证方法：每个候选公共字段都能指向两个独立的现有使用者。
- 完成条件：维护者可以根据证据选择外部工具、窄执行器或继续普通 Python。

### 交付一个受限制的执行模型

- 动作：仅在证据支持的范围内定义步骤身份、输入输出绑定、失败停止和恢复规则。
- 原因：首个实现必须解决已观察的问题，不能预建任意步骤图或万能状态机。
- 影响范围：独立 workflow 层、操作结果绑定、运行记录和用户文档。
- 交付物：一个覆盖两条真实工作流的最小执行模型及迁移说明。
- 验证方法：两条工作流的正常执行、失败停止、恢复、重复执行和 artifact 身份测试。
- 完成条件：单个操作仍可独立运行；workflow 层不复制 Training、Sampling 或 Evaluation
  runtime，也不按任务名称分支。

### 决定外部工具与内置能力的边界

- 动作：比较继续使用普通 Python、接入外部编排工具和维护内置窄执行器的成本与责任。
- 原因：集群调度、队列、权限和远程重试通常已有专门工具负责。
- 影响范围：架构决策、extension 集成和部署文档。
- 交付物：明确采用方案、非目标、兼容边界和维护负责人。
- 验证方法：独立 extension 能接入而无需修改 core dispatch；外部工具对象不进入
  checkpoint 或任务配置。
- 完成条件：公共边界只包含 Stochaflow 必须拥有且已有重复使用证据的部分。

## 如何证明已经完成

- 至少两条真实工作流共用同一最小控制模型，并保持各操作可独立运行。
- 成功、失败停止、恢复、重试和重复执行均有端到端测试。
- 每个公共字段有两个独立使用者；任务私有语义没有进入 core。
- 公开文档清楚区分操作、显式顺序组合和通用工作流编排器。
- `SPEC.md`、`ARCHITECTURE.md` 和 `CHANGELOG.md` 只在行为真正实现时同步更新。

## 明确不包含什么

- 不因计划文档存在就承诺通用步骤图、并行或远程调度。
- 不提供万能 `run(kind=...)`、任意 Python 对象图或按任务名称分支的执行器。
- 不接管训练、采样、恢复或 Evaluation 的配置与失败规则。
- 不在重复使用证据出现前实施任何运行时代码。
- 不把 Physics/KD 清理或 Extension 导入性能作为前置。
