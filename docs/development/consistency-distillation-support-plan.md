# Consistency Distillation 支持计划

> 文档类型：功能计划
>
> 工作状态：候选（Candidate）
>
> 当前可用性：不可用。框架能在训练中使用一个不更新的教师模型，但还没有可直接运行的
> Consistency Distillation 任务。

## 蒸馏想减少的是实际等待，而不只是配置里的步数

普通 diffusion 模型通常要反复调用同一个模型，逐步把噪声变成图片。教师模型可以生成质量
不错的结果，却可能需要几十次调用。Consistency Distillation 的想法是让一个学生模型学习
这段过程的结果，使它从带噪图片出发，只用一次或少量几次调用就得到最终图片。

真正有用的结果不能只是“采样步数从 50 改成了 4”。学生还要在相同数据、随机种子和生成数量
下保住足够的质量，并确实减少等待时间、显存占用和模型前向调用。训练完成后，用户只需要学生，
不应为了生成图片继续携带教师。

仓库已经允许训练任务加载并冻结一个辅助模型，也允许训练代码同时调用教师和学生。这说明现有
训练循环能够承载首个蒸馏任务，但并不表示算法、教师文件、学生采样和质量基线已经存在。
要把这些底层能力变成一项可验收的开发工作，还需要选定教师 checkpoint、训练数据、学生
模型以及质量和速度目标。根 [`ROADMAP.md`](../../ROADMAP.md) 尚未把它选为 `Next`；在这些
选择明确以前，继续扩展蒸馏接口只会把算法假设提前写进框架。

## 第一版让学生直接预测最终图片

首版选择 endpoint consistency：给学生一张处在某个噪声程度的图片，让它直接预测最终的干净
图片。训练时固定教师、噪声程度的配对方法、随机种子和对照实现，并提供 MSE 与 Pseudo-Huber
两种损失。MSE 会直接放大较大的像素误差，适合作为最容易核对的对照；Pseudo-Huber 会平滑
异常大的误差，便于判断训练不稳定是否只是被少数样本主导。还可以加入 clean anchor，也就是
额外要求学生在收到干净图片时保持它不变。

这个范围故意不包含“在任意两个噪声时刻之间转换”。先把从当前状态直达终点的离散方案做对，
才能判断更复杂的轨迹或连续时间方法是否真的解决了首版的缺陷，而不是同时更换太多假设。
首个任务也只做无条件图像生成；类别、文字和低清图片等条件留给有明确数据与评估方法的后续任务。

实现所需的确定性变换应来自 Gaussian 算法族自己的数学能力。蒸馏训练不能从采样模块反向导入
算法，也不能再复制一份相同公式。这样，教师采样和学生训练依赖的是同一含义，而不是两套看似
相同、以后可能各自变化的实现。

## 教师要先变成一份可以核对的训练输入

用户开始蒸馏前，需要从一个明确选择的 checkpoint 导出教师生成所需的文件。这组可搬到另一台
机器的文件记录教师权重、噪声过程、模型输出含义和导出版本。读取时必须在训练开始前检查这些
内容；缺文件、版本不符或含义不兼容都直接报错，不能在蒸馏代码里重新猜教师原来如何工作。

这一步填补了现有 frozen-teacher 能力最重要的空白：框架现在可以使用一个已经构造好的冻结模型，
但还没有受维护的教师导出格式和严格读取路径。将来把“训练教师”和“蒸馏学生”接成顺序工作流
时，交给下一步的也正是这份明确的教师文件，而不是一个裸路径或临时 Python 对象。

## 训练中三个模型副本必须各守各的职责

一次蒸馏训练会同时存在三个模型副本：冻结教师提供目标，学生接受优化，学生的平滑副本提供更
稳定的训练目标。只有学生参数进入优化器；教师不计算梯度；平滑副本只在一次优化确实成功后更新。
如果训练中断后继续，这三个副本、更新次数和随机状态都必须恢复到与连续训练相同的位置。

现有 `TrainingBuilder` 可以准备并声明教师，`TrainingStrategy` 可以组合教师和学生的前向计算，
而核心训练循环继续只管理一个自动优化器。教师与平滑副本属于训练期资产；学生 checkpoint 中
只保存以后继续训练和生成所需的内容。删除教师文件后，已经训练好的学生仍然必须能够采样。

## 用户从教师走到学生，再看完整的质量—速度曲线

用户会先准备教师 checkpoint、与教师兼容的数据和噪声设置，再导出教师文件并启动学生训练。
训练得到的学生 checkpoint 可以继续训练，也可以在另一个进程中独立生成图片。一步采样只调用
学生一次；少步采样由任务自己管理加噪、去噪、随机数和步骤记录，固定种子时可以重放。

正式 Evaluation 会在相同输入下比较教师的 1、2、4、8、50 次调用和学生的 1、2、4、8 次调用，
同时报告生成质量、干净图片重建、延迟、显存和实际前向次数。训练日志不能代替这份结果，也不能
只挑一个最好看的点。当前独立评估机制的用法见
[独立 checkpoint Evaluation](../configuration/workflows.md#独立-checkpoint-evaluation)。

这条流程还要经得住中断和替换。教师文件必须能在独立进程中读取后完成学生训练；教师始终不
更新，学生平滑副本只在优化成功后变化，继续中断的训练与连续训练一致。一步采样要能证明只调用
学生一次，少步采样要能按固定种子重放，而且学生推理既不读取教师文件，也不保存只在训练期
使用的状态。

为了确认这不是首个模型碰巧可用，还要由独立扩展替换学生模型而不修改核心运行代码。完整的
质量—速度曲线、相关测试、静态检查、配置参考和严格文档构建全部通过后，已经验证的行为才进入
公开文档。

## 哪些蒸馏想法留到首版之后

以下方向继续保留，但必须由首版结果或新的具体任务证明需要，不能预先堆成可空配置：

| 未来方向 | 重新考虑的条件 |
| --- | --- |
| 任意两个噪声时刻之间的转换，包括 Consistency Trajectory、连续时间 VP/VE 和 Heun | 首版“直接到最终图片”的离散方案在可重复实验中确实不足 |
| 随训练方式变化的学生平滑副本（target EMA）、可训练附加状态或 dropout | 对照实验证明固定更新或无 dropout 限制质量，并且这些状态能可靠继续训练 |
| 类别、文字或低清图片条件，包括 CFG、引导教师和 consistency 超分 | 一个具体条件任务或超分任务被选择，数据和评估方法已经确定 |
| Latent、文字到图片或多模态蒸馏 | Latent Diffusion 或 Stable Diffusion 的基础能力已经完成 |
| 感知损失、对抗损失或预先保存教师输出 | 正式结果或教师计算成本证明有必要；多优化器训练另行设计 |
| 多设备教师/学生和分阶段蒸馏对照 | 单设备实测无法满足需求，或研究基准明确要求分阶段蒸馏 |
| 独立优化器、交替更新、手动反向传播和通用蒸馏格式 | 获选算法无法使用当前单优化器循环；公共格式还需要两个真实任务 |
| 将原型提升为长期维护的内置任务或公共能力 | 完整结果证明值得维护，并出现第二个真实使用方 |
